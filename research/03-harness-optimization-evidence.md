# 03 — Harness optimization: evidence, mechanisms, and limits
> Slice: HarnessOptimizationResearch · Researched 2026-10-08 · Scope: What changes when model weights stay fixed but tools, editing, context, prompts, or execution control change.

## Narration-ready takeaways
- A coding agent’s score is not just a model score. In the peer-reviewed SWE-agent study, the same GPT-4 Turbo solved 11.00% of SWE-bench Lite with a shell-only agent and 18.00% with its purpose-built agent–computer interface. [1]
- Small interface choices can have measurable consequences: SWE-agent’s edit tool scored 15.0% without linting and 18.0% with it; retaining only the last five full observations scored 18.0%, versus 15.0% with full history. These are separate ablations, not gains we can add together. [1]
- CodeAct showed that giving the same model executable Python actions could outperform individual text or JSON tool calls. GPT-4 Turbo scored 74.4% on its 82-task tool benchmark with code actions, versus 52.4% with JSON actions—but code could do more work in each turn. [2]
- Better harnesses do not necessarily mean more elaborate harnesses. Agentless demonstrated a competitive fixed workflow, and Terminal-Bench found that its minimal terminal agent could outperform some larger systems while OpenAI’s Codex CLI remained stronger for the GPT models tested. [3][6]
- Memory can help without retraining: in the peer-reviewed Dynamic Cheatsheet study, GPT-4o’s Game of 24 accuracy went from 19% with the same instructions but empty memory to 99% with curated, retrieved memory. That is a highly repetitive arithmetic task, not evidence of a universal coding improvement. [15]
- Harness optimization can itself be automated. ADAS, AFlow, and the Darwin Gödel Machine all demonstrated improvements with frozen execution models; their search and extra inference still consume compute. [17][18][19]
- GEPA showed that prompt optimization can sometimes outperform weight-training under the study’s rollout budgets. It did not show that prompting always beats reinforcement learning: GRPO performed better on the study’s AIME-2025 evaluation. [22]
- In a first-party experiment, LangChain reported moving GPT-5.2-Codex from 52.8% to 66.5% on Terminal-Bench 2.0 by changing the surrounding system rather than the model. The published post does not provide a confidence interval or a held-out generalization test for that improvement. [24]
- In Can Bölük’s first-party editing experiment, Grok Code Fast 1 went from 6.7% with patch editing to 68.3% with hashline editing. Those are results on synthetic React mutations, checked against original files—not a tenfold improvement on real-world software engineering generally. [9]
- There is no universally best edit format or context policy. Published studies contain reversals across models, tasks, and feedback conditions, including cases where more instructions, memory, or reasoning made results worse. [1][2][11][13][15][16][24]
- The next step is not simply “replace the vendor’s harness.” OpenAI documents training its models for its patch format, while DeepSeek’s September 2026 report describes training across several different harnesses, including Claude Code, OpenCode, Pi, and DeepSeek Harness. [29][31]

## Findings

### What “only the harness changed” does—and does not—establish

For this dossier, a **harness-only comparison** keeps the execution model’s weights fixed while changing externally implemented prompts, tools, observations, context construction, memory, or control flow. SWE-agent explicitly studies a fixed language model; CodeAct separates off-the-shelf action-format experiments from subsequent model fine-tuning; GEPA distinguishes prompt parameters from model parameters. [1][2][22]

There are several different strengths of evidence, which should not be merged into one headline:

1. **Component ablation:** change one part of a system, as in SWE-agent’s editor, search, viewer, and history experiments. This gives comparatively direct evidence about that component in that configuration. [1]
2. **Whole-system comparison with a fixed model:** HAL, Terminal-Bench, and Claw-SWE-Bench compare harness–model pairs. These capture the effect of the whole package, including differences in tools, stopping rules, prompts, and sometimes effective compute budgets; they do not isolate which component caused the difference. [5][6][30]
3. **Frozen-model optimization:** ADAS, AFlow, GEPA, and DGM search for better prompts or executable orchestration. “No weight updates” does not mean “no training-like search,” “no additional information,” or “no additional cost.” [17][18][19][22]
4. **Within-task versus across-task adaptation:** Live-SWE-agent synthesizes tools while solving an individual issue; Dynamic Cheatsheet and online ACE accumulate information across a sequence of tasks; offline ACE and GEPA optimize using separate training data. These are different deployment/evaluation regimes. [15][16][21][22]
5. **Developer case study:** a vendor or maintainer’s report can provide valuable operational evidence, but it is not automatically an independently replicated causal experiment. LangChain, Anthropic, OpenAI, Aider, and Bölük disclose different amounts of experimental detail. [7][8][9][24][25][26][27][28]

[INFERENCE] The defensible thesis is **“harness design can materially change realized capability with the same model,”** not “the harness always matters more than the model” or “omp is therefore better than all competing harnesses.” The latter claims would require controlled comparisons that these studies do not supply. [1][5][6][9][30]

### Controlled interface evidence: SWE-agent and CodeAct

**SWE-agent — NeurIPS 2024, confirmed proceedings.** The model is `gpt-4-1106-preview`; the ablation set is SWE-bench Lite’s 300 instances, with a $4 per-instance budget. Table 1 reports **11.00% shell-only → 18.00% SWE-agent** when both receive a demonstration. The often-quoted **10.7 percentage-point gain** uses the **7.33% shell-only without demonstration** baseline, so it is not the cleanest headline for isolating the custom interface from demonstration differences. The full benchmark result, **12.47% on 2,294 tasks**, must not be substituted for the Lite ablation score. [1]

Table 3 supplies unusually concrete mechanisms: no specialized editor **10.3%**, editor without linting **15.0%**, editor with linting **18.0%**; iterative search **12.0%**, summarized search **18.0%**; full-file viewing **12.7%**, 100-line windows **18.0%**; full history **15.0%**, last five observations **18.0%**. Crucially, iterative search was worse than providing no specialized search at all (**15.7%**): agents exhaustively stepped through results and wasted their budgets. [1]

**CodeAct — ICML 2024, confirmed PMLR proceedings.** Its fixed-model experiments cover 17 off-the-shelf LLMs. On M³ToolEval, 82 human-curated tasks, GPT-4 Turbo’s code actions achieved **74.4%**, versus **52.4% JSON** and **53.7% text**; mean turns were **5.5**, **7.6**, and **7.7**, respectively. Twelve of 17 models performed best with code actions. The zero-shot, maximum-10-turn setup gives Python the ability to compose tools, reuse variables, loop, and branch within one action; it is therefore an action-space/runtime change, not just a cosmetic serialization swap. [2]

CodeAct also contains counter-evidence: on **atomic** API-Bank calls, GPT-4 Turbo scored **82.7% with JSON versus 76.7% with code**. Its fine-tuned CodeActAgent results are a separate contribution and are **not harness-only evidence**, because those experiments update weights. [2]

### Agentless, OpenHands, HAL, and Terminal-Bench

**Agentless — FSE 2025 / Proceedings of the ACM on Software Engineering, confirmed via ACM DOI metadata and the conference program.** Agentless uses a prescribed localization → repair → validation pipeline instead of letting an LLM select arbitrary next actions. Its final paper reports **32.00% / 96 fixes / $0.70 average inference cost** on 300 SWE-bench Lite issues with `gpt-4o-2024-05-13`. This is competitive evidence for simpler orchestration, but the cross-product leaderboard is not a controlled single-variable experiment: many baselines use different models, costs, or externally reported runs. [3]

Its **within-Agentless ablations** are more suitable here. Holding total candidate patch count at 40, using one greedy localization gives **29.33%**, merging multiple localizations gives **28.33%**, and generating ten patches separately for each of four localization samples gives **32.00%**. File skeletons also improve related-element localization from **56.67% to 62.00% contains-ground-truth**, while reducing that stage’s reported average cost from **$0.15 to $0.02**. The latter is a localization metric, not an issue-resolution rate. [3]

**OpenHands — ICLR 2025, confirmed proceedings.** This is primarily a platform/generalist-agent paper, not proof of a universal harness improvement. It provides sandboxed execution, an event stream, reusable skills, and delegation. Its CodeActAgent v1.5 comparison on **68 ML-Bench instances** is relevant: with `gpt-4-1106-preview`, SWE-agent achieves **42.6%**, while OpenHands achieves **58.8%**, with reported average costs **$1.91 and $1.22**. Treat it as a reported cross-system result, not an isolated edit-tool ablation; the same paper is explicit that its agents do not lead every task. [4]

**HAL — ICLR 2026, confirmed proceedings.** HAL separates an **evaluation harness** from the **agent scaffold** under test and studies models, scaffolds, and benchmarks jointly. Its principal study includes **21,730 rollouts, nine models, nine benchmarks, about $40,000**, and released traces. On SWE-bench Verified Mini’s **50-task** subset, its appendix reports GPT-4.1 at **2.0% / $51.80** with the HAL Generalist Agent and **44.0% / $393.65** with SWE-Agent; GPT-5 Medium is **12.0% / $57.58 → 46.0% / $162.93**. Costs here are for the benchmark evaluation, not per successful issue. These are whole-scaffold, unequal-cost contrasts, not evidence that a single tool yields those gains. [5]

HAL’s aggregate finding is nuanced: task-specialized scaffolds beat the generalist on **9 of 12 CORE-Bench Hard** comparisons and **11 of 12 SWE-bench Verified Mini** comparisons, while the generalist is cheaper in **20 of 24** comparisons. Higher reasoning effort gives equal or lower accuracy in **21 of 36** model–scaffold–benchmark comparisons. Neither specialization nor more reasoning wins universally. [5]

**Terminal-Bench — ICLR 2026, confirmed proceedings.** The published paper evaluates supported combinations at least **five times per task**, across **89 Terminal-Bench 2.0 tasks**, totaling **32,155 trials**; it reports 95% confidence intervals. Same-model contrasts in Table 2 include Gemini 2.5 Pro **15.7% ± 2.6% OpenHands → 32.6% ± 3.0% Terminus 2**, Claude Opus 4.5 **52.1% ± 2.5% Claude Code → 57.8% ± 2.5% Terminus 2**, and GPT-5 **35.2% ± 3.1% Terminus 2 → 49.6% ± 2.9% Codex CLI**. Thus, the paper supports both the value of minimal scaffolds and the value of a vendor-matched scaffold. [6]

The paper itself argues that model selection is usually more important than scaffold choice in its tested range. That is not a refutation of harness effects; it is a warning against replacing a model-only story with an equally simplistic harness-only story. These are historical study results, not October 2026 leaderboard rankings. [6]

### Editing format evidence—and common misquotations

**Aider’s historical edit experiments — first-party, grade C.** The frequently repeated **“GPT-4 Turbo 26% → 59%” is misattributed**. Aider’s laziness/refactoring report says **`gpt-4-1106-preview` 20% → 61%**, and **older `gpt-4-0613` 26% → 59%**, when moving from SEARCH/REPLACE blocks to Aider’s unified-diff approach on **89 Python refactoring tasks**. The older model could not fit **28%** of those tasks into its context window. These are not the separate 133-exercise coding benchmark, and the edit implementation also includes high-level-hunk prompting and flexible application. [7][8]

Aider’s earlier 133-exercise benchmark found plain-text formats superior to its then-new function-call formats; GPT-4’s whole-file and diff results were comparable, but whole-file output cost more and took longer. Only one configuration—`gpt-3.5-turbo-0613` with whole-file output—was repeated ten times to characterize variation; the author explicitly did not repeat all combinations that way. These findings concern historical APIs/models, not a general rule against modern structured tool calls. [8]

**Can Bölük’s hashline experiment — first-party, grade C.** The requested canonical lead `blog.can.ac/2026/02/12/the-harness-problem/` currently redirects to **Stencil’s “We improved 15 LLMs at coding in one afternoon. Only the harness changed.”** The article is dated **2026-02-12**; its accessed body describes **16 models**, **three runs × 180 tasks**, fresh sessions, and mutation-reversal fixtures sampled from React. It reports **Grok Code Fast 1 6.7% → 68.3%**, **Grok 4 Fast output tokens −61%**, and patch failure rates **50.7% for Grok 4** and **46.2% for GLM-4.7**. These are author-run results; no independently replicated confidence interval is supplied in the article. [9]

The accessed page also contains a newer chart-caption statement: hashline beats patch in **14/16 models**; a **v2 revision improves further in 12/16**; its largest named gain is **GPT-5.1 Codex Mini 60.0% → 77.5%**. The page does not clearly date that revision. Keep the original narrative’s numbers and the newer chart caption separate; “all 15 models improved” is not an accurate description of the accessed page. [9]

Hashline tags line content with short identifiers and refuses edits whose identifiers no longer match the read state. [INFERENCE] This shifts some correctness responsibility from exact reproduction of old text to an external anchor check; the experiment does not establish that hashing alone, independently of the rest of its edit interface, caused every gain. Scoring compares the resulting file against the original, before and after formatting, so semantically correct alternative fixes can be missed; the author acknowledges this limitation. [9]

**Can It Edit? — COLM 2024, accepted-paper list confirmed.** This studies following editing instructions, not a competition between patch syntaxes. It contains **105 handcrafted Python tasks**, each with descriptive and “lazy” instructions. GPT-4 pass@1 is **63.33 versus 51.95**, with 20 sampled completions per problem; the descriptive prompt contains more guidance, so the result is evidence for instruction/context quality, not an information-matched wording change. The EditCoder fine-tuning results change weights and are excluded from harness-only effect claims. [10]

**Diff-XYZ — NeurIPS 2025 Deep Learning for Code in the Agentic Era workshop presentation; latest quantitative source is arXiv v2, 2025-11-17.** It holds the code-pair data fixed while changing representations or prompt definitions, using **1,000 single-file edits from 891 repositories**, five languages. It separates parsing, application, and final exact match. For GPT-4.1, adding an explicit unified-diff definition changes diff-generation exact match **0.34 → 0.76** and parsing **0.43 → 0.99**; a separate format-plus-example experiment gives unified-diff **0.81 → search/replace 0.95**. Do not combine baseline cells from these two experiments. [11]

The revision matters: **v1’s abstract said search/replace was not well suited to diff analysis; v2 says it performs best for larger models across most tasks.** The official workshop page still carries the older abstract. Use v2’s quantitative results, and do not present v1’s conclusion as current. This dossier conservatively grades the revised numeric results B because their relationship to the workshop-reviewed version was not established. [11][12]

### Context engineering: positive results with explicit limits

**Lost in the Middle — TACL 2024, confirmed ACL/publisher record.** Position and amount of context affect otherwise-fixed models. In synthetic retrieval with **300 key–value pairs**, `gpt-3.5-turbo-16k-0613` has a **45.6% worst-position score** without query-aware contextualization and **100%** when the query is placed before and after the data. However, the same intervention produces little improvement—and slight harm in some positions—on multi-document question answering. Its older-model positional findings are a mechanism demonstration, not proof that every October 2026 model has the same curve. [13]

**Chroma’s Context Rot — first-party technical report, conservatively grade C.** The July 2025 report evaluates **18 LLMs** and includes controlled synthetic length experiments as well as LongMemEval. Its LongMemEval experiment compares focused answer-relevant excerpts with full conversation histories averaging **about 113k tokens**, after manually filtering to **306 prompts**. The plotted Claude Sonnet 4 non-thinking scores are **0.89 focused versus 0.38 full**. This is not purely “same information, more tokens”: the full condition also requires retrieving the right evidence from a much larger history. Do not translate the chart into “every agent loses 51 points at 113k.” [14]

**Dynamic Cheatsheet — EACL 2026 Long Papers, confirmed ACL record.** The strongest headline, GPT-4o **10% → 99% Game of 24**, combines better instructions and memory. The more informative memory comparison is **DC-empty 19% → DC-RS 99%**, with a 100-problem sequence and the same generator instructions. On AIME 2024, Claude 3.5 Sonnet is **23.3% baseline, 36.7% empty-memory, 50.0% cumulative-memory**; that benchmark has only **30 questions**. Generation and curation use the same LLM, while the retrieval variant uses `text-embedding-3-small` and top-three retrieval. Gains depend on discovering reusable strategies; Claude’s Game of 24 improvement is only **12% → 14%**. [15]

**ACE — ICLR 2026, confirmed proceedings; latest arXiv v3 is 2026-03-29.** All Generator/Reflector/Curator roles use DeepSeek-V3.1 in non-thinking mode, explicitly avoiding distillation from a stronger curator. On AppWorld, offline ACE with labels improves the paper’s average across normal/challenge TGC/SGC from **42.4 to 59.4**; without labels, it reaches **57.2**. Online ACE reaches **59.5**, but its best configuration includes offline warmup, so this must not be described as starting with no prior adaptation. Online evaluation predicts on a test item before updating context from that item; it is sequential learning, not independent task inference. [16]

ACE’s v3 adds broader-model and domain experiments plus stronger discussion of feedback quality. Its finance results explicitly show harm without reliable feedback: FiNER **70.7 baseline → 67.3 online ACE without labels**. The familiar abstract “+10.6%” averages over selected comparisons; the exact AppWorld rows are clearer for narration. [16]

[INFERENCE] These sources support **selecting and preserving useful context**, not minimizing context at any cost: SWE-agent benefits from dropping stale observations; ACE benefits from retaining detailed reusable knowledge instead of collapsing it into an overcompressed summary. Those interventions solve different information problems. [1][14][16]

### Automatically designing the harness

- **ADAS / Meta Agent Search — ICLR 2025.** A meta-agent writes executable agent designs and evaluates them against a growing archive. With fixed executor `gpt-3.5-turbo-0125`, DROP F1 rises from the strongest hand-designed Role Assignment baseline **65.8 ± 0.9 to 79.4 ± 0.8**; intervals are 95% bootstrap intervals. Search uses a stronger `gpt-4o-2024-05-13` proposer; the DROP experiment has 128 validation and 800 held-out test questions. This is frozen-executor evidence, not evidence that the weak executor invented the improvement unaided. [17]
- **AFlow — ICLR 2025.** It searches code-represented workflows using an MCTS variant. With GPT-4o-mini-0718, held-out HumanEval-subset pass@1 rises from **87.0 direct invocation to 94.7**, or **91.6 → 94.7** against its best hand-designed baselines. Data are split validation:test **1:4**, results averaged over three runs; these are not scores on untouched full HumanEval. More calls can be hidden inside one workflow output, so “pass@1” is not “one LLM call.” [18]
- **Darwin Gödel Machine — ICLR 2026; arXiv v3, 2026-03-12.** DGM modifies coding-agent code with frozen foundation models. The widely quoted **20.0% → 50.0% SWE-bench** result is on a selected **200-task Verified subset**, not all 500 Verified tasks. Full Polyglot improves **14.2% → 30.7%** using o3-mini for execution; Claude 3.5 Sonnet (New) handles self-modification. Its stronger generalization demonstration transfers the agent evolved on SWE-bench to entirely unseen Polyglot, **14.2% → 28.9%**. Eighty evolution iterations, additional retries/selection, and API expense remain part of the story; no weights are recursively improved. [19]
- **SICA — arXiv v2, 2025-05-16; grade B here.** It reports **17% → 53%** on a fixed random 50-question SWE-bench Verified subset, in a roughly **$7,000 / 15-iteration** search. This is **not a pure single-model comparison**: most agents use Sonnet 3.5 v2, but its reasoning subagent uses o3-mini. Its short **300-second** timeout makes editing/runtime efficiency particularly consequential. The authors report much weaker gains when the base reasoning model is already strong. [20]
- **Live-SWE-agent — arXiv v3, 2025-11-24; grade B.** Same-model Verified comparisons include Claude 4.5 Sonnet **70.6% mini-SWE-agent → 75.4% Live-SWE-agent**, average issue cost **$0.56 → $0.68**; the implementation uses `claude-sonnet-4-5-20250929`, one submitted patch per issue, 500 issues, 250 steps, and $3/issue limits. Baseline results are reused rather than all rerun in one campaign. Despite the broad “self-evolving scaffold” framing, §2.1 explicitly says the **agentic loop is unchanged**; the demonstrated mechanism is prompted synthesis and revision of executable tools during a run. [21]
- **GEPA — ICLR 2026 oral; arXiv v2, 2026-02-14.** The clean frozen-weights contrast is Qwen3-8B HotpotQA **42.33 baseline → 62.33 GEPA**, or **55.33 MIPROv2 → 62.33 GEPA**, on a 300-example test split after 150 training and 300 validation examples. Its GRPO comparison is a comparison of optimization methods, not same-weight harness ablation: GRPO changes weights. The famous “up to 35× fewer rollouts” refers to the best IFBench checkpoint at **678 rollouts versus 24,000**, not GEPA’s entire allocated IFBench budget of **3,593**. [22]
- **Meta-Harness — arXiv v1, 2026-03-30; grade B.** Claude Code with Opus 4.6 proposes new harness code after inspecting prior source, scores, and raw traces through a filesystem. GPT-OSS-120B classification improves from ACE **40.9 to 48.6 average accuracy**, with additional context **50.8k → 11.4k tokens**. Its Terminal-Bench Haiku 4.5 result is **37.6%**, versus a reported Goose **35.5%** and Terminus-KIRA **33.7%**. **The coding search and final evaluation use the same 89 tasks**, and comparator scores come from the public leaderboard. This is benchmark-specific discovery evidence, not held-out proof of superior general coding performance. [23]

**A newer external harness comparison:** Claw-SWE-Bench **v2, 2026-09-28** compares seven harnesses with three fixed models over 350 issues, three runs per pair, common task prompts, containers, patch collector, and 3,600-second outer timeouts. With Qwen 3.6-flash, GenericAgent scores **38.5%**, Hermes Agent **62.8%**; with GLM 5.1 they score **62.9% and 73.1%**. Native system prompts/tool interfaces/stopping behavior remain intentionally different. Its Meta-Harness-seeded variants improve, but the paper explicitly warns that those variants were evolved on the evaluation tasks and are not fair equal-information comparisons. [30]

### First-party harness-engineering accounts

**LangChain, 2026-02-17.** The `gpt-5.2-codex` **52.8% → 66.5%** Terminal-Bench 2.0 result bundles system-prompt guidance, environment context, pre-completion verification reminders, loop detection, and reasoning-budget allocation. The post reports **89 tasks** and Harbor/Daytona execution, but not a full repeat-count/CI table. It explicitly warns against overfitting a task. It also reports **53.9% at xhigh versus 63.6% at high**, with the former losing tasks to timeouts; its final “reasoning sandwich” reaches **66.5%**. This is still fixed-model optimization, but not fixed inference compute, and the post does not isolate the causal contribution of every middleware. The “Top 30 → Top 5” statement is the author’s February snapshot, **not a current rank as of 2026-10-08**. [24]

**Anthropic, “Writing effective tools,” 2025-09-11.** Anthropic describes improving internal Slack/Asana tools with Claude Code and testing on held-out tasks. Its concrete principles include consolidating repeated operations, clearer names/descriptions, semantic identifiers, concise outputs, and actionable errors. It gives an illustrative tool-response size comparison **206 tokens detailed versus 72 concise**, not an overall task-completion effect size. The article also says more tools and extra overlapping functionality can make agents worse; model-specific evaluation is necessary. [25]

**Anthropic, “Effective harnesses for long-running agents,” 2025-11-26.** With Opus 4.5 and the Claude Agent SDK, compaction alone did not reliably carry app development across context windows. An initializer, feature checklist, progress artifacts, incremental work, and browser testing improved its internal demonstrations. The initializer and coding “agents” differ in initial user prompt; their system prompt, tools, and underlying harness were otherwise identical. The post provides no standardized score, sample count, or CI, and explicitly leaves open whether a generalist or multi-agent architecture is best. [26]

**Anthropic, “Code execution with MCP,” 2025-11-04.** It reports an example reducing context tokens **150,000 → 2,000**, described as **98.7%**, by loading tool APIs on demand and keeping intermediate data in code rather than routing it repeatedly through the model. The article does not supply a model-specific controlled accuracy evaluation, number of runs, or uncertainty interval for this number. It is evidence for an architectural efficiency mechanism, not “MCP makes coding 98.7% better.” [27]

**OpenAI, “Harness engineering,” 2026-02-11.** This is an internal-product experience report: approximately a million lines of agent-written code, roughly 1,500 merged PRs over five months, and a human estimate of about one-tenth the time of manual coding. The team emphasizes repository-local knowledge, application observability, executable constraints, and feedback loops. **There is no controlled manual-team baseline or frozen-model intervention**, so neither the estimated speedup nor PR count belongs in a harness-only causal effect chart. [28]

**Mario Zechner’s pi run, 2025-11-30/December update.** The maintainer reports five trials per task with Claude Opus 4.5. His submitted `results.json` records a run beginning November 30 and finishing December 1, **445 total trials**, **71 errors**, and mean **0.4786516853932584**; its nested evaluation entry also reports **428 trials**, so do not silently treat every summary field as having the same denominator. If displayed as a percentage, **47.86516853932584% is a conversion of the recorded mean**, not a value printed by the source. This is useful evidence that a small harness can be competitive, not a before–after ablation or a model-controlled win over every competitor. His claim that results worsened when US Pacific hours began is a maintainer observation, not a demonstrated provider-causality result. [33][34]

### Mechanisms: why the surrounding software matters

| Mechanism | What the evidence actually shows | Narration/visual boundary |
|---|---|---|
| **Mechanical edit failures** | SWE-agent documents syntax-error cascades and improves with linting; Diff-XYZ separates malformed output, nonapplicable patches, and incorrect final content; the hashline experiment reports format-specific failure rates. [1][9][11] | Show “intended change → representation → application → correct program” as distinct gates; do not imply every failure is the harness’s fault. [1][11] |
| **Action granularity and composition** | CodeAct permits variables, loops, conditionals, and several tool operations in one code action; it reduces interaction turns in 12/17 tested models. [2] | Fewer model round trips can mean better budget use, but one code action can contain more primitive work than one JSON call. [2] |
| **Search/navigation ergonomics** | Summarized search beats iterative search in SWE-agent; exhaustive next-result loops exhaust budgets. Agentless’s skeleton input improves localization while reducing stage cost. [1][3] | “Show the relevant map, not every corridor,” with results tied to these specific studies. [1][3] |
| **Observation formatting and state** | SWE-agent displays updated file content after an edit, explains successful silent commands, collapses older observations, and uses targeted error feedback. [1] | External software can reduce state-tracking demands; no proof that one fixed window size is optimal for all modern models. [1] |
| **Retrieval burden and context interference** | Lost in the Middle isolates position effects; Chroma adds length/distractor experiments; full-history appending can underperform curated memory in Dynamic Cheatsheet. [13][14][15] | Separate “fits in context” from “uses the evidence correctly.” Avoid an invented universal context-decay curve. [13][14] |
| **Persistent reusable knowledge** | Dynamic Cheatsheet reuses discovered code/strategies; ACE uses itemized delta updates rather than rewriting the entire memory. [15][16] | Memory can preserve good strategies or amplify bad ones; show a feedback-quality gate, not magical learning. [15][16] |
| **Verification and stopping rules** | LangChain adds pre-completion reminders and time warnings; Anthropic’s long-running app agents need feature-level end-to-end verification. HAL finds verification correlated with success, not randomized proof of its causal magnitude. [5][24][26] | Say “supports recovery and checking,” not “a verification hook causes HAL’s entire observed advantage.” [5][24] |
| **Training–interface match** | OpenAI recommends its exact `apply_patch` because the model was trained for that format; Diff-XYZ finds GPT-4.1 sometimes emits V4A when unified diff was requested. [11][29] | Compatibility costs are real, but not proof that alternate tools cannot work. [29] |

### Counter-evidence, statistical caution, and the “bitter lesson”

**There are real negative and null results, not just missing evidence.** Iterative search hurts SWE-agent relative to no specialized search; CodeAct loses to JSON on some atomic tool calls; query duplication fails to fix multi-document QA; Dynamic Cheatsheet decreases GPT-4o’s MMLU-Pro Engineering score **53.2 → 51.2** under DC-RS; ACE’s no-label online FiNER result decreases **70.7 → 67.3**. In Diff-XYZ, adding a format definition improves GPT-4.1 diff generation but reduces GPT-4o-mini’s Apply exact match **0.70 → 0.05**. [1][2][11][13][15][16]

**More orchestration is not inherently better.** AFlow’s evaluated Self-Refine baseline averages **70.7**, below direct invocation **72.8** across its six metrics. GEPA+Merge degrades Qwen3-8B’s aggregate from GEPA’s **54.85 to 52.40**, despite helping other model/task combinations. On AIME-2025, GRPO scores **38.00**, above GEPA’s **32.00**. These counterexamples argue for evaluation-driven selection rather than a fixed “best practice” bag of tricks. [18][22]

**Separate repetition from selection.** SWE-agent’s six Lite runs range **17.33–18.67%**, average **17.94%**, while pass@6 reaches **32.67%**. That does not mean a user automatically gets 32.67% from one run: pass@k represents success across multiple candidates, and deployment needs a way to identify the correct result. Agentless similarly distinguishes its selected-patch performance from the higher upper bound when any sampled patch counts. [1][3]

**Confidence intervals need a specified target.** Terminal-Bench reports 95% intervals and at least five repetitions; Aider reports repeat variation only for one historical configuration; several vendor posts omit intervals altogether. [INFERENCE] For the video, display reported intervals when available, and use “reported” rather than “proved” for a small point-estimate gap without a paired difference analysis. Repetition on fixed tasks, uncertainty over new tasks, and provider/environment drift are different questions. HAL and Terminal-Bench both document infrastructure/API sources of instability. [5][6][8][24]

**A cautionary 2026 preprint:** “The Scaffold Effect” reports only **0–8-point** within-model success-rate differences on 50 Terminal-Bench Pro tasks while claiming much larger token differences. It has material internal inconsistencies: Table 2’s rates do not match several Table 4 solved counts, and the abstract excludes zero for the largest contrast while the printed **[−18.0, 0.0]** paired interval includes its zero endpoint. Its token accounting differs by harness. Consequently, this dossier does **not** use its “40×” claim as a reliable headline or effect-table anchor. [32]

**Cost is not a side issue.** HAL’s stronger specialized agents can cost more; Dynamic Cheatsheet’s Sonnet AIME-2024 average token counts are **370 baseline, 494 empty-memory, 1,035 DC-RS, 1,831 DC-Cu**; LangChain’s maximum reasoning caused timeouts. [INFERENCE] “Same model” comparisons should show success alongside input/output/cache tokens, elapsed time, retries, and offline optimization spend—not just model pricing. [5][15][24]

**Do models absorb harness tricks?** ADAS explicitly motivates automated discovery with the historical replacement of hand-designed components by learned ones. SICA reports marginal improvement on reasoning tasks and hypothesizes that crude reasoning scaffolds may interrupt already-trained reasoning. LangChain similarly calls some loop-detection guardrails temporary heuristics likely to become unnecessary. These are a mixture of observed limits and forward-looking author hypotheses, **not proof that all harness engineering will disappear**. [17][20][24]

**Training lock-in is a compatibility issue, not necessarily permanent vendor lock-in.** OpenAI’s current guide, accessed **2026-10-08**, explicitly recommends its exact patch implementation because its model has been trained for that diff format; it also says terminal-like tools can work and custom tools require tuning. [INFERENCE] This creates switching/tuning costs, but does not establish a technical prohibition on alternative harnesses. DeepSeek’s **2026-09-17** technical report gives a countertrend: RL across multiple Claude Code versions and heterogeneous OpenCode/Pi/DSH interfaces, normalized into a common trajectory schema, with checkpoint merging. Those improvements involve weight training and must not be counted as harness-only gains. [29][31]

## Contested or uncertain

- **Causality versus package effect:** shared model weights do not equalize inference compute, action granularity, helper-model contributions, prompts, or environment policy. The largest whole-system results should be labeled accordingly. [2][5][19][20][24][30]
- **Source revisions can reverse conclusions.** Diff-XYZ’s workshop abstract/v1 and v2 disagree about search/replace suitability for analysis; this dossier uses v2 numbers and flags the provenance boundary. [11][12]
- **Agentless has conflicting abstracts.** The FSE program still states **32.67%, 98 fixes, $0.68**; the final author-hosted paper and ACM DOI metadata state **32.00%, 96 fixes, $0.70**. The final paper notes that using the provided PASS_TO_PASS test list would yield 98 fixes, whereas its main setup avoids that list. Use the final paper’s main result, not the stale program abstract. [3]
- **Terminal-Bench’s published token-table caption says “all 74 tasks,” while its main study says 89.** The input-token totals also vary sharply by scaffold. Do not use the tempting Opus “65× token saving” derivation without resolving that caption/accounting discrepancy; the resolution-rate contrasts are separately stated in the same table. [6]
- **Hashline article revision and denominator details:** title says 15 models, body/caption says 16; its current caption discusses a v2 revision without a separate date; it says “four tools” but lists read/edit/write. These editorial inconsistencies do not disprove the experiment, but they argue for using only exact supported quantities and reviewing raw reports before a definitive comparative marketing claim. [9]
- **Current product comparisons:** Zechner’s November 2025 views about missing visibility/features and Bölük’s February 2026 competitor criticism are historical first-person accounts. This slice does not claim those gaps still exist in October 2026. [9][33]
- **Generalization is not interchangeable:** Meta-Harness’s classification experiments hold out tests, but its Terminal-Bench discovery does not. DGM’s cross-benchmark transfer is stronger evidence of generalization than its repeatedly assessed search subsets. [19][23]
- **Absence of uncertainty reporting is not absence of variance.** It limits how confidently a small measured gain can be narrated; a source’s “state of the art” phrase is dated to its experiment rather than silently promoted to a current ranking. [5][6][8][21][23][24]

## Corrections & nuances to the blueprint

- The core proposed claim is well supported, but **“only the harness” includes several distinct interventions**. An edit format change, curated memory, adaptive compute allocation, and a stronger-model-driven offline search should not be visually presented as equivalent experiments. [1][9][15][17][24]
- **Venues:** SWE-agent is NeurIPS 2024; CodeAct is ICML 2024; Agentless is FSE 2025; OpenHands, ADAS, and AFlow are ICLR 2025; HAL, Terminal-Bench, ACE, DGM, and GEPA are ICLR 2026; Dynamic Cheatsheet is EACL 2026; Can It Edit? is COLM 2024. Diff-XYZ has a NeurIPS 2025 **workshop** presentation, not main-track acceptance. [1][2][3][4][5][6][10][11][15][16][17][18][19][22]
- **Aider’s 26% → 59% belongs to the older June GPT-4, not GPT-4 Turbo.** For Turbo, the report is 20% → 61%, on a specialized refactoring benchmark. [7]
- **“Can It Edit?” is not a diff-format ablation.** Its instruction-detail comparisons are relevant, but its learned EditCoder improvements require model fine-tuning. [10]
- **“Self-improvement” is not necessarily self-training.** DGM and SICA change agent code with frozen models; Live-SWE-agent primarily creates tools without changing the loop; GEPA changes prompts. DeepSeek’s multi-harness RL changes weights and belongs to a separate co-design story. [19][20][21][22][31]
- **No universal best harness or mixture architecture follows from this evidence.** Minimal systems win some settings, specialist systems win others, and additional reasoning/reflection/memory can hurt. This slice supports configurable, measurable harness design—not an unconditional feature-count argument for omp. [1][2][5][6][15][18][20][22]
- OpenAI’s “one-tenth the time” and Anthropic’s long-running-agent demos are useful practitioner narratives, **not randomized productivity findings or same-model benchmark ablations**. [26][28]

## Open questions for the user

1. Should the introduction lead with the strongest **peer-reviewed, older-model causal example** (SWE-agent), or the most directly omp-related **first-party hashline result**, with its synthetic-task limitations stated on-screen?
2. Is the intended promise “more reliable editing,” “higher autonomous task success,” “lower cost,” or “better human control”? These require different headline metrics; which should the video prioritize?
3. Should automatically self-modifying harness research be framed as a research frontier, or should the video recommend users actually enable self-modifying systems? This dossier establishes evidence for the former, not an operational safety recommendation for the latter.
4. Is a clearly labeled practitioner anecdote acceptable for the visual hook, provided peer-reviewed evidence and counterexamples follow immediately?

## Visual ideas

- **Frozen model, interchangeable interfaces:** keep the model icon unchanged while shell-only, custom editor, and linting modules change. Use SWE-agent Table 1 for the whole-system comparison and Table 3 for separate ablation bars; never animate the deltas as an additive waterfall. [1]
- **Two-sided harness matrix:** rows = models, columns = scaffolds, cells = success rate and interval. Highlight Gemini’s advantage with Terminus 2 and GPT-5’s advantage with Codex CLI so the comparison is fair rather than anti-vendor. [6]
- **Four gates to an edit:** intent → valid format → applicable edit → tests pass. Use Diff-XYZ’s parsing/application metrics and a short illustrative hashline anchor—not an uncited claim that anchor matching proves semantic correctness. [9][11]
- **Context “signal, not size” diptych:** one side shows irrelevant histories being filtered; the other preserves detailed reusable insights during an ACE update. Label the Chroma chart “focused excerpts vs full history; retrieval burden differs.” [14][16]
- **Automatic design timeline:** ADAS/AFlow → DGM/SICA → GEPA/Meta-Harness; distinguish code search, prompt search, and weight-training in separate lanes. Use publication dates/venues in References rather than equating preprint dates with conference acceptance. [17][18][19][20][22][23][31]
- **Honest uncertainty panel:** six SWE-agent run scores beside pass@6, and a separate Terminal-Bench plot with reported 95% intervals. The visual point is that reruns and selecting among attempts are different operations. [1][6]
- **Cost–success scatterplot:** use one internally consistent table, such as HAL Table A23 or Claw-SWE-Bench Table 2; do not merge different datasets, pricing dates, or token-accounting conventions into a single frontier. [5][30]
- **Negative-result reversal:** flip from CodeAct’s complex-task gain to its atomic JSON win, or from a Diff-XYZ GPT-4.1 gain to GPT-4.1-nano’s loss. This supports “measure on your model and task,” not “one format wins forever.” [2][11]
